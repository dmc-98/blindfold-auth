# Blindfold Auth — Microsoft Entra ID OIDC Example

Quick-start for enterprise SSO via Microsoft Entra ID (formerly Azure Active Directory).
**Full guide: [`docs/sso/entra.md`](../../docs/sso/entra.md)**

## Steps

```sh
# 1. Register an app in Azure Portal (see docs/sso/entra.md Step 1)
# 2. Validate the IdP metadata
npx blindfold sso doctor \
  --url "https://login.microsoftonline.com/{tenantId}/v2.0/.well-known/openid-configuration"

# 3. Fill in credentials
cp .env.example .env

# 4. Register the provider + binding (run once)
npm run setup

# 5. Start the server
npm start
# → http://localhost:3000
```

## Environment variables

| Variable | Where to find it |
|----------|-----------------|
| `ENTRA_CLIENT_ID` | Azure Portal → App registrations → your app → Overview |
| `ENTRA_TENANT_ID` | Azure Portal → App registrations → your app → Overview |
| `ENTRA_CLIENT_SECRET` | App registrations → Certificates & secrets → Client secrets |
| `ENTRA_DOMAIN` | Your company email domain, e.g. `contoso.com` (optional) |
| `BLINDFOLD_WORKSPACE_ID` | Generated by `blindfold bootstrap` |
| `BLINDFOLD_SECRET` | Generated by `blindfold bootstrap` |

## Callback URL to register in Azure

```
http://localhost:3000/auth/sso/oidc/callback
```

Add this under: App registrations → Authentication → Redirect URIs

## Troubleshooting

See the **Troubleshooting** table in [`docs/sso/entra.md`](../../docs/sso/entra.md#troubleshooting).
Common issues: `AADSTS50011` (redirect URI mismatch), `state mismatch` (check cookies).
